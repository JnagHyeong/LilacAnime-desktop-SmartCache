# LilacAnime 지능형 메모리 캐싱 기능 구현 상세 설명

LilacAnime 데스크톱 환경에서 네트워크 버퍼링을 없애고 연속적이며 매끄러운 영상 시청 환경을 제공하기 위해 구현된 **지능형 메모리 캐싱 및 끊김 없는 재생(Seamless Playback) 시스템**의 상세 기능과 기술적 구현 내역

## 1. 🛠️ 개요 및 설계 목표

* **목표:** 사전에 시청 중인 작품의 회차 60%지점에서 미리 다음회차의 데이터를 캐싱하여, 사용자가 다음 회차로 넘어갈때 버퍼링이나 로딩 지연 없이 계속해서 작품을 시청할 수 있도록 보장합니다. 또한, 타임라인 탐색(Seeking) 중 발생할 수 있는 전환 과정에서 시스루 캔버스 스냅샷을 활용하여 UX측면에서 이질감이 들지 않게 합니다.

* 불필요한 디스크 I/O를 최소화하고 빠른 접근이 가능한 램(RAM) 기반 캐싱을 활용하되, 기기 사양(모바일/데스크톱)에 따른 리소스 상한선을 관리하여 시스템 안정성을 극대화합니다.

## 2. 주요 기능 상세

### ① 백그라운드 스마트 프리페치 (Smart Prefetch)

* **동작 시점:** 현재 재생 중인 영상의 진행도가 **60%**를 초과하는 순간 백그라운드에서 자동으로 다음 회차 준비를 시작합니다.

* **병렬 다운로드 최적화:** 다음 회차의 HLS 조각(Segment) URL들을 분석한 뒤, 동시 접속 제한(`CONCURRENCY_LIMIT = 4`)을 두어 대역폭 독점을 막고 청크들을 안정적으로 병렬 수집합니다.

* **용량 제한 가드 (Capping):**

  * 회차별 최대 캐시 용량 제한 (`MAX_EPISODE_BYTES`: 모바일 70MB / 데스크톱 150MB)

  * 전체 캐시 용량 상한선 (`MAX_CACHE_BYTES`: 모바일 200MB / 데스크톱 450MB)

  * 용량 초과 시 가장 오래된 캐시(LRU 방식)를 순차적으로 자동 소거하여 메모리 압박을 방지합니다.

### ② MediaSource 기반 메모리 즉시 재생 (Blob & MSE Playback)

* **버퍼링 없는 즉시 진입:** 이미 메모리에 캐싱된 에피소드 선택 시, 네트워크 통신 지연이나 버퍼링 대기 없이 `MediaSource`와 `SourceBuffer`를 통해 `.ts`/`.mp4` 바이너리 데이터를 직접 주입하여 즉시 재생을 시작합니다.

* **듀레이션 보정:** 캐싱 시점에 계산된 전체 재생 시간(`calculatedDuration`)을 `MediaSource`에 사전 할당하여 플레이어 타임라인 바와 총 재생 시간이 오차 없이 매끄럽게 연동되도록 보장합니다.

### ③ 가변형 시스루 캔버스 스냅샷 (Dynamic See-Through Canvas Snapshot)

* **구현 사유:** 캐시되지 않은 외부 구간으로 시킹(Seeking)하거나 스트리밍으로 전환할 때, 버퍼링 대기 시간 동안 화면이 검게 변하거나 멈추는 시각적 끊김(Flash) 현상이 발생하여 사용자 경험을 해칩니다. 이를 자연스럽게 가리기 위해 스냅샷 오버레이 기법을 도입했습니다.

* **구현 방식 (가변 캔버스 적용):**

  * 시킹 직전, 현재 재생 중인 비디오 엘리트의 프레임을 가변형 `<canvas>`에 즉시 캡처합니다.

  * 이때 캔버스의 해상도는 **영상의 실제 원본 크기(`videoWidth`/`videoHeight`)**를 우선 반영하며, 메타데이터가 미처 로드되지 않은 예외 상황에서는 **플레이어 DOM의 가시적 크기(`clientWidth`/`clientHeight`)**를 폴백으로 사용하여 고정 크기로 인한 화질 저하 및 왜곡을 방지합니다.

  * 캡처된 캔버스는 `object-fit: contain` 및 절대 위치(Absolute) 스타일이 적용되어 전체 화면이나 창 크기 변경 시에도 반응형으로 완벽하게 동작합니다.

* **부드러운 전환 흐름 (Handoff):**

  * 캡처된 스냅샷 오버레이를 플레이어 상단에 띄워 사용자가 마치 정지 화면을 보는 것처럼 자연스럽게 유지합니다(`z-index: 20`).

  * 새로운 HLS 스트림의 버퍼링이 완료되고 재생 준비(`canplay` 이벤트)가 끝나는 순간 스냅샷 오버레이를 안전하게 제거(`remove()`)하여 시각적인 이질감 없이 영상으로 복귀시킵니다.

### ④ 레이스 컨디션(Race Condition) 방어 및 생명주기 관리 (`HlsCacheManager`)

* **세션 및 요청 검증:** `cacheSessionId`와 `playbackRequestId`를 통해, 사용자가 빠르게 연속으로 다른 회차를 클릭하거나 화면을 이동할 때 구형 비동기 네트워크 요청 및 버퍼 주입 태스크를 즉시 무효화(`Abort`)하여 충돌과 자원 낭비를 방지합니다.

* **TTL 딥 클린업 (Deep Cleanup):** 작품 상세 페이지나 플레이어를 이탈한 뒤 **60초** 동안 재진입이 없으면 타이머가 작동하여 메모리에 남아있는 블롭(Blobs), `SourceBuffer`, 객체 URL(`URL.revokeObjectURL`)을 일괄 해제합니다.

* **전전 회차(N-2) 자동 정분:** 현재 재생 중인 기준으로 2단계 이전(N-2)의 오래된 캐시 데이터를 실시간으로 감지하여 메모리에서 비워줌으로써 쾌적한 가용 램(RAM) 용량을 유지합니다.
